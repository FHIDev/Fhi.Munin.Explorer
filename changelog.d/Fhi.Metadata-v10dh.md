category: Fixed
- **Signing out and back in while the variable lists are being read no longer leaves the list view waiting on a read that never comes.** Before, the new reader's read was turned away because the previous reader's read was still in flight. When that read landed it was rightly ignored, but nothing asked again, so the view said «Henter variabellistene dine …» with nothing reading until some other surface happened to re-render. The new reader's read now starts at once. The previous reader's read still writes nothing when it lands, and it can no longer end the new read early, which would have let another surface send the same read twice. If the previous reader's read fails after the new reader's lists have landed, that failure is now dropped as its answer would be, instead of replacing the new reader's lists with «Kunne ikke hente listen».
