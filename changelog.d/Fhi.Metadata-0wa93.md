- **Copying a variable list, or saving a shared one as your own, reads the list on screen once instead of three times, and no longer leaves controls for a list deleted elsewhere.** The view reloaded the page for every change the copy's own follow-up reads raised, then read it again itself, so one copy cost three reads of the same page, and three requests against the rate limit, whether or not reading the lists again succeeded. And if the list on screen had been deleted in another tab, rename, copy and delete stayed drawn for it and the picker named no option. The view now waits for its own follow-up reads before reading the page once, and moves to another list when the one shown is gone. Pressing «Lagre listen» again while a shared list was being saved saved it twice; a second press now does nothing until the save is done, and the button is marked aria-disabled meanwhile, as the copy button is. Nothing draws that state yet: Stiler styles aria-disabled on `button-square--ghost`, not on the `--ghost-blue` these buttons wear.
