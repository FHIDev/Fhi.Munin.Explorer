- **A finding in unchanged code is Pre-existing** - The pre-PR reviewer tags a finding Important or Nit, and marks it Pre-existing when it is in code the pull request does not change, as `REVIEW.md` defines it: a scope beside the severity, so a Pre-existing Important stays Important. A Pre-existing finding starts no new review round and is not fixed in the pull request; a Pre-existing Important always gets a follow-up bead, or a bead proposal to the owner where the owner files beads, and the pull request lists each. A later round does not repeat an earlier round's findings. The same rule is in DevInfra's `REVIEW.md` and team rules. (DevInfra-og3.46)
