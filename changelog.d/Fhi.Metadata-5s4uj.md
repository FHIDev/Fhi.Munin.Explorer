category: Fixed
- **The saved list's kilde filter stays after «Fjern» or a save.** It used to go blank after any write to the list until the reader switched list and back. A removal now counts the variable's kilde one down, and a save from the explorer's save button counts it one up, with no extra request. A kilde whose last variable leaves drops out of the filter, and its tick goes with it, so the list is never narrowed to a kilde that is no longer shown. A host that adds variables through the public `VariableListState.AddVariablesAsync` or `ToggleSavedAsync` still sees the filter go blank until the reader switches list, because neither says which kilde a variable belongs to.
