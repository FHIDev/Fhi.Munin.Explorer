category: Added
- **A reader who is not signed in can keep a variable list in their browser, behind a feature flag.** With `MuninExplorer:Features:AnonymousLists` on, the save button in `VariableSearch` is offered to a signed-out reader and adds the row to one list kept in the browser's local storage; the list tab shows it, downloads it in the formats a saved list offers, shares it as a code (while the snapshot stays under the share endpoint's 512 KB, about 990 full rows), and empties it after a confirmation. Each row holds catalogue fields only: `variabelId`, `variabelCode`, `variabelName`, `kildeId`, `kildeName`, `kildeKortNavn`, `datasamlingId`, `datasamlingName`, `variabelgruppeName`, `dataType`, `dataFrom`, `dataTo` and `versjonStatus`; at most 2000 rows. Signed in with rows still in the browser, the list tab offers «Lagre som ny liste i Mine lister», which creates a new list and adds every row to it in one request, so Munin saves all of them or none, and then takes the saved rows out of the browser. When Munin refuses the request and names variables, such as one whose row's datasamling is no longer its own, nothing is saved: the new list is deleted again, every row stays in the browser, the reader is told how many rows of how many variables were refused, and «Fjern radene for disse variablene» takes every row of those variables out of the browser so the rest can be saved. Refused rows are not remembered: kept, the next press is refused the same way. Any other failure saves nothing either, deletes the new list and keeps every row. When the delete fails too, as it can under the same write limit, an empty list can be left in Mine lister; the reader can delete it. Nothing is carried over without that press.
- **`IMuninExplorerClient.ExportItemsAsync` exports a list nobody has saved, one line per (variable, datasamling).** It is the supported successor to the obsolete `ExportListAsync`, on the same anonymous route, and carries a default body, so a host implementing the contract itself still builds.
