category: Notes for hosts
- **The dataperiode fields are `input[type="text"]` with `inputmode="numeric"` beside a calendar button, no longer `input[type="date"]`.** Each field and its button sit in a new `div.munin-explorer-filters__date` row, and the button wears the new `munin-explorer-filters__date-button`; both need a rule in `Fhi.Helsedata.Stiler` (the sample stylesheets carry one: a flex row, and a 34px square button with the field's border). The button opens a hidden native `input[type="date"]` wearing `screenreader-only`, which must stay clipped. A stylesheet that styles `.munin-explorer-filters input[type="date"]` now reaches only that hidden input, so that rule can go; the text field takes the general `.munin-explorer-filters input[type="text"]` rule. Each field also has a `p.caption` hint between its label and the row, named by its `aria-describedby`. `munin-explorer-date-picker` is not a class and needs no rule: it is read out of the button's `data-munin-explorer-date-picker`, which names the hidden input it opens. The package's browser module no longer exports `readDateInput` and now exports `watchDatePickers`, one page-wide click listener.
