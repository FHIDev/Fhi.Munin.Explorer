category: Added
- **The Explorer shows Munin's English names and descriptions on English pages.** With `Language` set to English, the kilde, delkilde, datasamling, variabelgruppe and variable names and descriptions the components draw — the kilde list, the detail views, the variable rows and their panels, the filter tree and its chips (whose names the API already resolves against `Accept-Language`), the trails and the hierarchy — is shown in English where Munin sent English for that field, and in Norwegian, marked `lang="no"`, where it did not. Each field falls back on its own, so an English name can stand over a Norwegian description. Norwegian pages are unchanged. Sorting and search still read the Norwegian names. The saved-list rows and the descriptions in a variable's version history stay Norwegian, because the API sends no English for them yet. Hosts change nothing.
- **The contracts carry the English names Munin now sends for variable rows and the hierarchy's groups, and the Norwegian name beside each facet's.** `VariableSummary.PreferredTermEn`, `KildeNameEn`, `DatasamlingNameEn` and `VariabelgruppeNameEn`, and `HierarchyVariabelgruppe.NameEn`, each null when Munin has no English. `NameNo` on `KildeFacet`, `DelkildeFacet`, `DatasamlingFacet`, `VariabelgruppeFacet` and `FilterFacet` is the Norwegian name whatever the request's `Accept-Language`, which a facet's `Name` follows; it is null from an older API.
