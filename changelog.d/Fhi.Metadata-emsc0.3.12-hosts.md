category: Notes for hosts
- **`MuninExplorer:Features:AnonymousLists` is off by default; turning it on stores a list in the reader's browser.** The key is `Fhi.Munin.Explorer:anonymous-list` in local storage, kept by the package's existing `explorer-interop.js`. Every change re-reads the stored list, so another tab's change stands for every row a page has not touched; for a row a page changed while the browser refused to store it, that page's unsaved change wins. Where the reader's browser refuses storage, the list lasts while the page is open and the list tab says so. A host that does not serve that module has no browser list at all: the save button and the list tab say the list cannot be kept in this browser. Nothing is stored about the reader, and the package shows no consent text: whether the host's privacy statement needs a line about it is the host's call. The list needs a list tab to be seen: `VariableExplorer`, or `VariableSearch` given a `VariableList` fragment holding `VariableListView`; `VariableSearch` mounted alone offers a signed-out reader no save button. The carry-over at sign-in writes to Munin under its per-reader write limit: one create and one add of every row, all or nothing, and one delete of the new list when nothing is saved. A press only ever deletes the list it created; when that delete fails, or the reader signs out during the press, the new list can be left in Mine lister, and the reader can delete it. Where a host implements `IMuninExplorerClient.AddItemsToMyListAsync` itself, an `HttpRequestException` with status 400 reads as a refusal that names no variables: nothing is saved and the reader gets the general failure sentence. The change adds no class name.
