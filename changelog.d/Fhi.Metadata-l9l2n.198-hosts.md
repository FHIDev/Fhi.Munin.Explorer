category: Notes for hosts
- **Every new feature a reader can see, merged from 20 November 2026 on, arrives behind a `MuninExplorer:Features` key of its own, off by default.** A host updating the package gets no such feature until it sets that key to `true` in an environment's appsettings; work merged before then keeps its place, so in this release the browser list for a signed-out reader stays on `CodePicker`, and the message at Munin's list quota arrives unflagged, as a change of text; fixes, changes of text, accessibility fixes and changes of styling arrive unflagged, and a follow-up to a flagged feature comes behind that feature's key. Each key is removed once helsedata has had it on in production through a release, and its feature then stays on; this replaces 2.19.0's note that a key is removed once its feature is on for every host. A removal is named here when it happens, as BREAKING for a host that sets `options.Features.<Name>` in code. The README's «Turning features on per environment» lists every key with the release that added it. The Munin API routes a feature calls are not flagged. `CodePicker` and `AdvancedSearch` are unchanged. (Fhi.Metadata-l9l2n.198)
