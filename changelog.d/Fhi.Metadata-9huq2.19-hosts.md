category: Notes for hosts
- **Two class names are no longer emitted, so Fhi.Helsedata.Stiler's rules for `.munin-explorer-lead` and `.munin-explorer-kodeverk__reference` can be removed.** The kodeverk lead sentence is gone, and each code list's reference is now in its heading. The heading keeps its place and its classes (`.headline.munin-explorer-group`, directly before a `ul.munin-explorer-kodeverk`), so `.headline.munin-explorer-group` and `[role=tabpanel] > .munin-explorer-group:first-child` apply as before; the change is that every link now has its own heading and a `ul` of one `li.munin-explorer-kodeverk__item`, so the item's bottom border (`:last-child`) no longer separates two links of one kind — the heading's own margin does. (Fhi.Metadata-9huq2.19)
- **The code picker's search hits and tree scroll in one box.** A long list (Bokommune, ABR, any list of 200 codes) no longer pushes «Lagre» and «Avbryt» far below, even after a search, when the hits and the full tree show together: the new `munin-explorer-codetree-scroll` wraps the hits (with their «Velg treffene»/«Fjern treffene») and the tree, and gets `max-height: 60vh`, `overflow-y: auto`, `overscroll-behavior: contain` and 2px padding so a focus ring is not cut; the search field stays above it. `.munin-explorer-codetree` itself gets no height cap. A focused code scrolls itself into view. The samples' `host.css` has the rule; Stiler's comes with Fhi.Metadata-9huq2.16. (Fhi.Metadata-9huq2.19)
- **The chosen codes show in the list row's «Ønskede data» cell again, in their own box above the note.** The new `munin-explorer-dataitem-main__desiredCodes` wraps the summary; the textarea stays the cell's direct child. Below 1280px, where the cell is a two-column grid with the data-label first, the box needs `grid-column: 1 / -1` and the textarea `grid-column: 2`, or the textarea drops into the label column; at every width, a 4px gap under the box. The samples' `host.css` has these rules; Stiler's come with Fhi.Metadata-9huq2.16. (Fhi.Metadata-9huq2.19)
